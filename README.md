# 2026 原力萌芽 幸福親子園遊會 — 活動回饋問卷

跟攤位報名系統同一套做法：前端放 GitHub Pages，後端是 Google Apps Script，資料寫進 Google 試算表。

```
index.html          問卷頁面（所有題目在同一頁）
css/style.css       樣式（跟報名系統同一套配色）
js/config.js        ← 部署後只要改這個（貼 Apps Script 網址）
js/questions.js     題目＋編碼規則（跟 gas/questions.gs 一模一樣）
js/form.js          畫出問卷、作答、一機一次、送出
assets/fju2026.jpg  主視覺
gas/Code.gs         Apps Script 後端
gas/questions.gs    = js/questions.js 的複製
```

## 部署步驟

### 1. 建 Apps Script 後端

1. 開一份新的 Google 試算表（名字隨意，例如「原力萌芽 問卷回覆」）。
2. 上方選單 **擴充功能 → Apps Script**。
3. 把預設的 `程式碼.gs` 內容全部刪掉，貼上 `gas/Code.gs`。
4. 左邊「檔案」旁的 **＋ → 指令碼**，命名為 `questions`，貼上 `gas/questions.gs`。
5. 上方函式選單選 **setup**，按 **▶ 執行** → 跳出授權就按允許。
   執行完，試算表會多出「回覆」和「代碼對照表」兩張工作表。
6. 右上角 **部署 → 新增部署作業**：
   - 類型：**網頁應用程式**
   - 執行身分：**我**
   - 具有存取權的使用者：**所有人**（一定要選這個，不然手機會送不出去）
7. 按「部署」，複製「網頁應用程式網址」（`https://script.google.com/macros/s/……/exec`）。
   用瀏覽器打開這個網址，看到 `"message":"問卷後端運作中"` 就代表成功。

### 2. 設定前端

打開 `js/config.js`，把網址貼到 `GAS_URL`。

### 3. 放上 GitHub Pages

兩種放法都可以：

- **開一個新的 repo**：整個資料夾丟上去，Settings → Pages 打開。
- **放在報名系統的 repo 裡**：把這個資料夾改名成 `survey/` 放進去，網址就是 `…/survey/`。
  想在填完的畫面放「回到攤位報名系統」按鈕的話，把 `config.js` 的 `HOME_URL` 設成 `'../'`。

### 4. 測試

1. `config.js` 的 `TEST_MODE` 先改成 `true`。
2. 用手機填一次，確認試算表「回覆」多了一列。
3. 填完的畫面會有「刪除這支手機的紀錄，再填一次」（要連按兩次），
   按下去會把**這支手機送過的那一列從試算表刪掉**，手機也恢復成沒填過，可以反覆測。
   - 忘記開測試模式就先填了也沒關係：把 `TEST_MODE` 打開再打開問卷，一樣會看到這顆按鈕，
     之前那一筆一樣會被刪掉。
   - 只刪得到「這支手機」的紀錄；用別支手機或無痕視窗填的，要自己到試算表刪。
4. **活動前**：最後一次測完先按這顆按鈕把那一筆刪掉，再把 `TEST_MODE` 改回 `false`。
   打開「回覆」確認只剩標題列。

## 服務台領獎怎麼核對

填完的畫面會用大字顯示他填的名字，並提醒他到服務台（A1 攤位旁）報名字，領小熊軟糖、轉扭蛋。
服務台可以：

- 直接看他手機上的完成畫面（再打開也還是會顯示名字），或
- 在試算表「回覆」用 Ctrl+F 搜 `Q1_姓名` 那一欄。

問卷如果跟攤位報名系統放在同一個網域（例如放在報名系統 repo 的 `survey/` 資料夾），
玩家報名攤位時填過的名字會自動帶進姓名欄，他可以再改。

## 試算表裡的資料長什麼樣子

| 題型 | 存法 | 例子 |
|---|---|---|
| 姓名 | 一欄存原文（服務台核對領獎用） | `Q1_姓名` |
| 單選 | 一欄，依選項順序 1、2、3… | `Q3_身分`：學生 = 1、教職員 = 2、校外人士 = 3 |
| 複選 | 每個選項一欄，勾 = 1、沒勾 = 0 | `Q6_族群_客家人` = 1 |
| 「其他」 | 單選：代碼照存；複選：`…_其他` = 1；另外多一欄 `…_其他說明` 存文字 | `Q2_性別` = 3、`Q2_性別_其他說明` = 自己寫的字 |
| 綜合問題 | 每個項目一欄，1 = 非常滿意 … 5 = 非常不滿意 | `Q9-1_場地安排` = 2 |
| 建議 | 一欄存原文 | `Q10_建議` |
| 哪一族 | 有勾「原住民」才會問；沒勾的人這十八欄全部是 0 | `Q6a_族別_阿美族` |

每一欄的完整代碼說明都在試算表的「代碼對照表」工作表。

最前面兩欄是 `時間戳記` 和 `裝置ID`（判斷一台手機只能填一次用的）。

## 一台手機只能填一次：怎麼做的、擋得住什麼

- 手機第一次打開問卷時，會產生一組隨機的裝置 ID，存在瀏覽器裡（localStorage 和 cookie 各存一份）。
- 送出成功後瀏覽器會記住「已填過」，再打開只會看到「這支手機已經填過問卷囉」。
- 後端也會檢查這個裝置 ID 有沒有出現過，所以連按兩下、網路斷掉自動重送，都不會變成兩筆。

擋不住的情況：用**無痕視窗**、**清除瀏覽器資料**、或**換另一個瀏覽器**（例如 LINE 內建瀏覽器 → Safari）再開一次。
網頁沒有辦法在不要求登入的情況下真正認出「同一支手機」；
用手機型號、螢幕大小來猜也不行，因為現場會有一大堆同型號的 iPhone，反而會把不同的人擋掉。
一般民眾不會特地這樣做，對活動問卷來說夠用了。

## 之後要改題目

1. 改 `js/questions.js`（題目、選項都在最上面的 `SURVEY`）。
2. 把 `version` 改成新的字串（例如 `'2026-11-10a'`）。
3. 把整個檔案再貼一次到 Apps Script 的 `questions.gs`。
4. Apps Script **部署 → 管理部署作業 → ✎ 編輯 → 版本選「新版本」→ 部署**（網址不會變）。
5. 前端推上 GitHub。

如果已經有資料，新的題目欄位對不上，後端會把舊的「回覆」改名成「回覆_舊版_日期」保留，再開一張新的，舊資料不會被動到。

⚠️ 在選項中間插入新選項會讓後面的代碼往後移（例如花費 2000元以上 從 5 變 6），已經收到的資料不會自動跟著改，所以活動開始後就盡量不要改選項順序。
